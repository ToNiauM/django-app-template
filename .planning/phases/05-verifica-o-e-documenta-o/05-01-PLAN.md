<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Checkout do template → destino Copier | A árvore Jinja confiável materializa código executável em diretório temporário. |
| Shell do host → Docker daemon/Compose | O ensaio cria imagens, containers, rede e volume sob um projeto exclusivo. |
| `.env` efêmero → processos Django/PostgreSQL | Segredos descartáveis atravessam para containers sem pertencer às respostas Copier. |
| Porta loopback → cliente HTTP | O processo real é acessado somente por `127.0.0.1`, antes de qualquer proxy. |

## STRIDE Threat Register — ASVS L1

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `.env`, superusuário e logs do ensaio | high | mitigate | Gerar segredos no processo/destino temporário, omitir stdout/diagnósticos/answers e destruir `.env` no cleanup padrão. |
| T-05-02 | Tampering / Denial of Service | `limpar` e Docker Compose | high | mitigate | Projeto Compose único, destino `mktemp` registrado, expansões entre aspas, sem glob/prune e remoção exclusiva de recursos próprios. |
| T-05-03 | Information Disclosure / Elevation of Privilege | publicação do serviço `web` | high | mitigate | Resposta Copier mantém `WEB_BIND_ADDRESS=127.0.0.1`; smoke usa explicitamente loopback e o script falha se a configuração efetiva não validar. |
| T-05-04 | Tampering | dados interpolados em comandos shell | high | mitigate | Slug/banco internos alfanuméricos, porta numérica obtida localmente, nenhuma avaliação dinâmica e todas as expansões usadas como argumentos entre aspas. |
| T-05-05 | Repudiation | falso positivo de nascimento | medium | mitigate | Exigir em ordem config, boot, prontidão, migrate, createsuperuser, runner Django e dois smokes; qualquer status não zero propaga até o script. |
