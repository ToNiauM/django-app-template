<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client (HTMX Request) → Django Views | Parâmetros GET (`q`, `categoria`, `status`, `ordem`, `pagina`) e dados POST enviados pelo navegador |
| Browser Modal → Server | Submissão de dados de formulário com validação server-side e resposta de status 422 ou 200 |
| Application → Database Query Engine | Construção dinâmica de cláusulas WHERE e ORDER BY via ORM |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Injection | `apps/exemplo/views.py` (`item_listar_view`) | mitigate | Whitelist estrita `COLUNAS_ORDENACAO_PERMITIDAS` impede que parâmetros maliciosos no GET `ordem` cheguem ao `.order_by()`, caindo no fallback padrão `-criado_em` |
| T-03-06 | Injection | `apps/exemplo/views.py` (`item_listar_view`) | mitigate | Busca textual tratada exclusivamente via objetos `Q(titulo__icontains=q)` do ORM do Django com parametrização SQL automática contra SQL Injection |
| T-03-07 | Tampering | `apps/exemplo/forms.py` (`ItemExemploForm`) | mitigate | `ModelForm` com validação de campos obrigatórios e `clean_valor` rejeita submissões forjadas ou dados numéricos corrompidos retornando HTTP 422 |
| T-03-08 | Elevation of Privilege | `apps/exemplo/views.py` | mitigate | Todas as views protegidas com `@login_required` impedindo acesso anônimo ao CRUD |
| T-03-09 | CSRF | `apps/exemplo/templates/exemplo/_confirmar_exclusao_modal.html` | mitigate | Exclusão de itens processada via POST com token CSRF obrigatório (`{% csrf_token %}` e `CsrfViewMiddleware`) |
</threat_model>
