<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Navegador → `POST /login/` | Entrada não confiável (e-mail/senha, header `HX-Request`, parâmetro `next`) |
| Navegador → `POST /logout/` | Requer sessão válida (cookie), mas o POST em si não carrega dado sensível novo |
| `?next=` (querystring) → `HttpResponseClientRedirect` | Entrada controlada pelo cliente que decide para onde o navegador é redirecionado após login |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | `POST /login/` (força bruta) | mitigate | `django-axes` já configurado no Plan 01-01 (`AXES_FAILURE_LIMIT=5`, lockout por usuário+IP); testado nesta plan (6ª tentativa bloqueada) |
| T-04-02 | Tampering | CSRF em `POST /login/`/`POST /logout/` | mitigate | `CsrfViewMiddleware` (Plan 01-01) + token lido via `htmx:configRequest` (Plan 01-02, `base.html`) a cada request; round-trip provado por teste nesta plan |
| T-04-03 | Tampering (Open Redirect) | `?next=` em `login_view` apontando para host externo | mitigate | `login_view` valida `next` com `django.utils.http.url_has_allowed_host_and_scheme(..., allowed_hosts={request.get_host()})` antes de redirecionar; cai para `/` se inválido — testado explicitamente |
| T-04-04 | Information Disclosure | Cookie de sessão sem `Secure`/`SameSite` | mitigate | `SESSION_COOKIE_SECURE=True`, `SESSION_COOKIE_SAMESITE="Lax"` (Plan 01-01); `SESSION_COOKIE_HTTPONLY` fica no default `True` do Django, nunca sobrescrito |
| T-04-05 | Denial of Service | `AxesMiddleware` sobrescrevendo a resposta 200 correta por uma página genérica | mitigate | `AXES_LOCKOUT_CALLABLE` (Plan 01-02) já devolve a resposta original; testado nesta plan (6ª tentativa continua HTTP 200 com fragmento correto, não a página genérica do axes) |
| T-04-06 | Tampering | `redirect()` puro numa view acessada via HTMX aninhando a página inteira | mitigate | `login_view`/`logout_view` usam `HttpResponseClientRedirect` (nunca `django.shortcuts.redirect`); `HtmxRedirectMiddleware` (Plan 01-02) cobre qualquer 302 residual |
</threat_model>
