### Os três conflitos previsíveis num derivado que nasceu na v0.1.0

Um derivado que fez reskin à mão editou exatamente os três arquivos que esta fase
reescreve inteiros. O conflito é **certo** e **não viola o critério 7**, que fala de
arquivo que o derivado **não tenha tocado**:

| Arquivo | O que o derivado fez | Resolução |
|---|---|---|
| `core/templates/core/_nav.html` | apagou o item "Início", colou os itens do domínio | `git checkout --theirs` e recriar os itens em `core/templates/core/_nav_dominio.html`, uma linha por item com `{% item_nav %}` |
| `tailwind.config.js` | fixou a cor de marca no arquivo e acrescentou `borderRadius`/`fontSize`/`fontFamily` à mão | `git checkout --theirs`; a cor fixada à mão vai para `COR_PRIMARIA` no `.env`, **não** para o config — o config passa a ser verbatim e é reescrito a cada update |
| `core/static/src/input.css` | acrescentou o `@layer base { :focus-visible }` no topo | `git checkout --theirs`; qualquer token próprio de estado migra para `core/static/src/dominio.css`, que o update nunca toca |

Ordem do roteiro: (0) árvore limpa e branch de atualização; (1) `copier update --vcs-ref v0.2.0`;
(2) resolver os três arquivos ficando com a versão do template; (3) recriar o menu em
`_nav_dominio.html`; (4) mover tokens próprios para `dominio.css`; (5) transportar a cor
para o `.env`; (6) `docker compose up -d --build` (o CSS é artefato de build);
(7) rodar `manage.py test` do próprio sistema.

### Regressão completa da fase

```
bash .template-tests/ensaio_django.sh derrubar
bash .template-tests/test_copier_copy.sh
bash .template-tests/test_copier_update.sh
python3 -m unittest discover -s .template-tests -p 'test_*.py'
bash .template-tests/test_07_cor_runtime.sh
bash .template-tests/ensaio_django.sh derrubar
bash .template-tests/test_05_nascimento.sh --keep
```

O primeiro `derrubar` limpa o banco de ensaio que os planos 07-03 a 07-07 deixaram no host:
containers, volumes, o `dados/` (removido via container root, senão o uid 999 do initdb
impede o `rm`) e o diretório da cópia. O segundo `derrubar` refaz a limpeza depois da suíte
de cor em runtime, que recria o banco. Sem eles a regressão começa de um host sujo e o
ensaio de nascimento disputa recursos com um projeto Compose vivo.

`test_05_nascimento.sh` gera uma cópia real, sobe `db` + `web`, migra, cria administrador
de ensaio e roda `docker compose exec -T web python manage.py test core apps.exemplo
--noinput` (`test_05_nascimento.sh:197`) **dentro** dessa cópia. O `--keep` retém a cópia e
informa destino, projeto Compose e URL — é ela que o checkpoint inspeciona.

**Inventário de suítes ao fim da fase — medido, nunca decorado.**

O número "11" que circula no ROADMAP (critério 8) e no REQUIREMENTS (QA-03) **já era falso
antes desta fase**: `ls .template-tests/ | grep -c '^test_'` devolve **10** no HEAD atual
(`test_04_03_identity.py`, `test_04_04_optional_exemplo.py`, `test_04_05_backup.py`,
`test_04_06_operations.py`, `test_04_07_collectstatic.py`, `test_05_nascimento.sh`,
`test_06_persistencia.py`, `test_copier_copy.sh`, `test_copier_update.sh`,
`test_quick_comentarios_template.py`). A fase acrescenta três — `test_07_tokens.py`
(07-02/07-07), `test_07_nav_extensao.py` (07-03) e `test_07_cor_runtime.sh` (07-04) —, o
que projeta **13**. Mas o executor **não escreve 13**: ele roda

```
ls .template-tests/ | grep -c '^test_'
```

no momento da task e escreve o número medido. Qualquer número escrito à mão nasce
desatualizado na fase seguinte, e foi assim que "11" virou mentira.

`ensaio_django.sh` **não** é suíte — é ferramenta, e é por isso que o nome dele não começa
com `test_`; o `grep '^test_'` acima o exclui de graça, e é essa a razão da convenção de
nome fixada no plano 07-01.

**O texto do ROADMAP e do REQUIREMENTS perde o número.** Critério 8 e QA-03 passam a dizer
"todas as suítes de `.template-tests/`". Isto **não** enfraquece critério nenhum: 13 verdes
já satisfaziam "as 11 seguem verdes" com folga, e nenhuma verificação futura pode falhar
por causa da troca. O que se remove é um inteiro que nunca foi verdadeiro — dívida, não
contrato. O README fica com o inventário nomeado (a lista de arquivos, que é útil) e, se
citar quantidade, cita a medida.
