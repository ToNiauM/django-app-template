### Regras de derivação — verificadas numericamente no planejamento

Dois primitivos:

- `misturar(hex, alvo, fator)` — mistura sRGB canal a canal com um alvo (`255` = branco,
  `0` = preto). É a mesma matemática da `misturar()` que hoje vive no
  `tailwind.config.js.jinja` (removida pelo plano 07-02), portada para Python.
- `com_hsl(hex, fator_sat, luz)` — preserva o **matiz**, multiplica a **saturação** por
  `fator_sat` e fixa a **luminosidade** em `luz` (0..1). Usa `colorsys` da biblioteca
  padrão (`rgb_to_hls` / `hls_to_rgb`) — nenhuma dependência nova.

| Chave | Tema claro | Tema escuro |
|---|---|---|
| `brand` | `cor` | `com_hsl(cor, 1.00, 0.727)` |
| `brand-hover` | `misturar(cor, 255, 0.12)` | `com_hsl(cor, 1.00, 0.827)` |
| `brand-ink` | `misturar(cor, 0, 0.18)` | `com_hsl(cor, 1.00, 0.627)` |
| `brand-tint` | `misturar(cor, 255, 0.92)` | `com_hsl(cor, 0.50, 0.153)` |
| `seq-600` | `cor` | `com_hsl(cor, 1.00, 0.727)` |
| `seq-450` | `misturar(cor, 255, 0.34)` | `com_hsl(cor, 0.72, 0.567)` |
| `seq-300` | `misturar(cor, 255, 0.62)` | `com_hsl(cor, 0.55, 0.427)` |

### Valores de referência — o contrato numérico do teste

`familia_marca("#003c71")` (a cor do padrão de referência) tem que devolver exatamente:

| Chave | claro | escuro |
|---|---|---|
| `brand` | `#003c71` | `#74beff` |
| `brand-hover` | `#1f5382` | `#a7d6ff` |
| `brand-ink` | `#00315d` | `#41a6ff` |
| `brand-tint` | `#ebeff4` | `#14283b` |
| `seq-600` | `#003c71` | `#74beff` |
| `seq-450` | `#577ea1` | `#4196e0` |
| `seq-300` | `#9eb5c9` | `#3171a9` |

Onze dos doze batem **byte a byte** com o `input.css` do padrão de referência. A única
divergência é `brand-tint` escuro: o padrão publica `#14263a` e a derivação produz
`#14283b` — 2 pontos em um canal. É o **único** token da família sem regra derivável do
padrão (A2 da pesquisa); a divergência é esperada e **não deve ser "corrigida"** com um
valor cravado, porque um valor cravado não sobreviveria a uma `cor_primaria` diferente.

`familia_marca("#1e40af")` (o default do `copier.yml`) tem que devolver exatamente os
valores que o plano 07-02 escreveu no `:root` e no `[data-tema="escuro"]` do `input.css`:
claro `#1e40af / #3957b9 / #193490 / #edf0f9 / #1e40af / #6b81ca / #aab6e1`;
escuro `#889feb / #b4c2f2 / #5d7ce3 / #192035 / #889feb / #5873c9 / #435697`.

**Arredondamento:** use meia-para-cima (`int(x + 0.5)` para valores não negativos), não
`round()` do Python — `round()` usa arredondamento bancário e divergiria da `misturar()`
do JavaScript em empates. Os valores acima foram conferidos nas duas implementações.
