### O defeito, medido (G-04 / WR-04)

Os dois cards de gráfico são
`bg-surface … dark:bg-surface-2` (`dashboard.html:68` e `:79`). O script lê:

| Sítio | Lê hoje | No escuro dá | Deveria ler |
|---|---|---|---|
| `dashboard.html:170` — `splitLine.lineStyle.color` | `corSurface2` (`--cor-surface-2`) | `#22211d` sobre card `#22211d` = **1,00:1** | `corGrid` (`--cor-grid`) — é o token de LINHA |
| `dashboard.html:220` — donut `itemStyle.borderColor` | `corSurface` (`--cor-surface`) | `#181614` sobre card `#22211d` — separação mais escura que o card, inexistente no claro | o fundo REAL do card, mapeado por tema |

No tema claro o `splitLine` também está errado, só que discretamente: `--cor-surface-2`
sobre `--cor-surface` dá **1,09:1**; com `--cor-grid` vai a ≈ 1,29:1.

### O conserto

```js
// mapeamento de elevação, igual ao que os cards declaram em classe:
// claro -> bg-surface ; escuro -> dark:bg-surface-2
const corCard = temaAtual() === "escuro" ? corSurface2 : corSurface;

splitLine: { lineStyle: { color: corGrid } },        // linha lê o token de linha
itemStyle: { borderColor: corCard, borderWidth: 2 }, // separação lê o fundo real
```

`corGrid` já existe no escopo (`dashboard.html:136`) — nenhuma variável nova além de
`corCard`. Deixe um comentário de uma linha amarrando `corCard` às classes do card, para
que a próxima mudança de elevação encontre o mapeamento em vez de adivinhá-lo.

### Por que o teste consegue provar isto sem navegador

Não há headless browser neste repositório e não é hora de introduzir um. A prova possível
— e suficiente — tem duas metades encadeadas:

1. **Resolução no fonte.** O teste lê `dashboard.html`, extrai as ligações
   `const <ident> = lerVarCss("--cor-<token>");` do topo de `montarGraficos()` num dicionário
   `ident -> token`, depois casa `splitLine: { lineStyle: { color: <ident> } }` e
   `itemStyle: { borderColor: <ident>` e resolve cada `<ident>` para o token que ele
   carrega. Isso responde "qual variável CSS este elemento realmente usa" — que é
   exatamente o que o 07-06 assumiu sem verificar.
2. **Contraste computado.** Com o token em mãos, o teste pega o valor por tema em
   `tokens_do_input_css()` e mede o contraste contra o fundo do card do mesmo tema
   (`surface` no claro, `surface-2` no escuro), com o helper do plano 07-09.

Para `corCard`, que é ternário e não `lerVarCss` direto, assere a forma do mapeamento:
existe `const corCard = temaAtual() === "escuro" ? corSurface2 : corSurface;` e o
`borderColor` do donut usa `corCard`. E amarre ao HTML: os dois cards de gráfico declaram
`bg-surface` e `dark:bg-surface-2` — se alguém mudar a elevação do card e esquecer o
script, o teste acusa.

### Pisos de contraste, e por que não são 3:1

Linha de grade e separação de fatia são **cromo**, não objeto gráfico portador de
informação: elas não carregam dado, delimitam. O piso que fecha o gap é
**> 1,00** — hoje a grade escura está exatamente em 1,00:1, ou seja, ausente. Fixe o gate
em **≥ 1,25:1** nos dois temas: é margem suficiente para impedir uma regressão que troque
um token por outro quase idêntico, e é folgado para os valores reais
(≈ 1,29:1 no claro, ≈ 1,38:1 no escuro). Escreva esse raciocínio na docstring do teste —
um piso sem justificativa vira número mágico que alguém baixa na primeira falha.

O piso de 3:1 pertence ao dado, não ao cromo, e é o plano 07-13 que responde por ele.

### Os dois adjacentes do mesmo bloco

- **WR-13 (segurança).** `dashboard.html:158` e `:210` montam o retorno do `formatter`
  por template string, e o ECharts insere esse retorno como **HTML**. `p.name` vem de
  `rawCat.map(d => d.categoria)` e `params.name` de `d.rotulo`, ambos montados em
  `views.py:249` e `:257` como `dict(Choices.choices).get(item["x"], item["x"])` — com
  **fallback para o valor cru do banco**. `choices` é validação de formulário, não
  constraint de banco: um `queryset.update()`, uma migração de dados ou uma carga por SQL
  gravam qualquer string. Este dashboard é o artefato que todo derivado copia e adapta
  para dados de domínio de verdade, onde `name` **será** entrada de usuário.
- **IN-04.** `dashboard.html:112` faz `JSON.parse(elPaletaData.textContent)` sem o
  `|| "[]"` que as linhas 104-105 usam. Um `<script>` vazio lança `SyntaxError` e derruba
  os dois gráficos.

Ambos vivem nas mesmas duas funções que este plano já reescreve. Entram junto.
