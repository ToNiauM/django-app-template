### Assinatura nova de `item_nav` (o parâmetro entra no fim, posicional-compatível)

```
{% item_nav rota rotulo icone prefixo excecoes %}

item_nav(context, rota, rotulo, icone="", prefixo="", excecoes="")
```

`excecoes`: prefixos separados por espaço que **não** ativam este item mesmo estando sob
`prefixo` — as rotas-irmãs que têm item próprio no menu. Regra final:

```
sob_prefixo = bool(prefixo) and caminho.startswith(prefixo)
excluido    = any(caminho.startswith(p) for p in excecoes.split() if p)
ativo       = caminho == url or (sob_prefixo and not excluido)
```

A correspondência **exata** nunca é anulada por `excecoes` — um item continua ativo na
própria URL, aconteça o que acontecer. É o que impede que uma exceção mal escrita apague
o estado ativo do item dono da rota.

Por que declarativo e não inferido: uma `inclusion_tag` renderiza um item por vez, sem
estado compartilhado e sem enxergar os irmãos. Qualquer desempate automático dependeria
da ORDEM em que os itens aparecem no arquivo — frágil exatamente no arquivo que pertence
ao derivado. A exceção declarada no sítio da chamada é lida junto com o item que ela
governa.

### `nav_dominio` — inclusão tolerante (WR-10)

`_nav.html:18` faz `{% include "core/_nav_dominio.html" %}` sem guarda. O `{% include %}`
do Django com string literal levanta `TemplateDoesNotExist` quando o arquivo some — não
existe `ignore missing` (isso é Jinja2). O stub anuncia em letras maiúsculas "ESTE ARQUIVO
É DO SEU SISTEMA", o que convida um mantenedor de derivado a apagá-lo. Hoje o resultado é
**500 em toda página que estenda `shell.html`**.

```
@register.simple_tag(takes_context=True)
def nav_dominio(context):
    try:
        tpl = get_template("core/_nav_dominio.html")
    except TemplateDoesNotExist:
        return ""
    return mark_safe(tpl.render(context.flatten()))
```

`mark_safe` aqui é seguro e não é atalho: o conteúdo é um template renderizado pelo
próprio motor do Django, com autoescape já aplicado dentro do render — não é string vinda
de request. `context.flatten()` é o que faz `request` e o resto do contexto chegarem aos
`{% item_nav %}` de dentro do arquivo incluído.

### `request` ausente (WR-02)

`context["request"]` levanta `KeyError` em qualquer render que não passe pelo context
processor de request: `render_to_string()` sem `request=`, template de e-mail, geração de
PDF, comando de management. Troque por `context.get("request")` e, sem request,
`caminho = ""` — o item renderiza **inativo** em vez de derrubar o render.
