`login.html` no nível certo, contrato executável.

### Contrato do script de tema

- Aceita `"auto"`, `"claro"` ou `"escuro"`; qualquer outro valor cai em `"auto"`.
- Grava a preferência em `localStorage["tema"]`.
- Resolve escuro quando a preferência é `"escuro"`, ou quando é `"auto"` e
  `window.matchMedia("(prefers-color-scheme: dark)").matches`.
- Escreve `document.documentElement.setAttribute("data-tema", escuro ? "escuro" : "claro")`.
- Atualiza o `content` do `<meta id="meta-theme-cor">`: `#0f0e0d` no escuro, `{{ cor_primaria }}` no claro.
- Dispara `document.dispatchEvent(new CustomEvent("tema:alterado"))`.
- Registra um listener em `matchMedia(...).addEventListener("change", …)` que reaplica
  **apenas** quando a preferência guardada é `"auto"`.
- Roda uma vez na carga com `localStorage.getItem("tema") || "auto"`.

### Ordem obrigatória no `<head>` de `core/templates/base.html`

1. `<meta charset>`, `<meta viewport>`, `<title>`
2. `<meta name="theme-color" id="meta-theme-cor" content="{{ cor_primaria }}">`
   — **sobe** da linha 13 atual para cá, senão o script não encontra o elemento na
   primeira execução
3. `<script>` de tema — **síncrono**, sem `defer`, sem `async`, sem `{% static %}`
   (é inline curto de propósito)
4. `<link rel="stylesheet" href="{% static 'dist/tailwind.css' %}">`
5. `<style>{{ tema_css|safe }}</style>` (entregue pelo plano 07-04)
6. o resto (`manifest`, `icon`, htmx, alpine)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `localStorage` do navegador → `data-tema` do documento | Valor controlado pelo próprio usuário, lido por script que roda antes de qualquer CSS |
| logout → estado remanescente no cliente | `limparCachePwa()` decide o que sobrevive à sessão |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-13 | Tampering | valor arbitrário em `localStorage["tema"]` chegando a `setAttribute("data-tema", …)` | mitigate | O script normaliza a entrada num `switch` fechado de três valores (`auto`/`claro`/`escuro`); qualquer outro cai em `"auto"`. O que vai para `setAttribute` é sempre a string literal `"escuro"` ou `"claro"`, nunca o valor lido — o atributo não é ponto de injeção |
| T-07-14 | Information disclosure | preferência de tema persistida no cliente após o logout | accept | A chave `"tema"` guarda uma de três strings fixas: não é dado de sessão, não identifica o usuário e não revela conteúdo autenticado. Mantê-la é decisão de produto (D-99). O que **é** dado de sessão continua sendo apagado: `caches` completo e `localStorage["htmx-history-cache"]`, além do `hx-history="false"` no `<body>` |
| T-07-15 | Denial of service (visual) | script síncrono bloqueante no `<head>` atrasando o primeiro paint | accept | Script inline curto, sem I/O de rede, sem `{% static %}`; o custo é microssegundos e é o preço explícito de não ter flash de tema. Alternativa (script deferido) troca o custo por um bug visível a todo carregamento |
| T-07-16 | Tampering | `{{ cor_primaria }}` interpolado dentro do JavaScript do script de tema (valor do `<meta>` no claro) | mitigate | `COR_PRIMARIA` é validada como `#RRGGBB` no boot (`config/settings/base.py:152-161`, `ImproperlyConfigured`); e a interpolação acontece no atributo `content` do `<meta>`, com auto-escaping do Django, não numa string JS solta |
| T-07-SC | Tampering | instalação de pacote npm/pip/cargo | n/a | Nenhum pacote novo; Alpine e htmx já são vendorizados em `core/static/vendor/` desde a Fase 1 |
</threat_model>
