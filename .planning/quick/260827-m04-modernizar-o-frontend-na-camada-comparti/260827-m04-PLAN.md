<interfaces>
Fatos do código que travam a implementação (extraídos — não explorar de novo):

1. **Purge do Tailwind:** CSS solto (fora de `@layer`) sobrevive sempre; regra dentro de `@layer` só sobrevive se o seletor for classe presente no conteúdo varrido ou na safelist. Portanto: todas as regras novas de elemento/id/pseudo (`:root`, `::selection`, `#modal-container`, `tbody tr:hover`, `h1`, `a`, `button`, `@keyframes`, `@view-transition`, media queries) vão como **regras soltas**, no padrão já usado pela paleta e pelo `[x-cloak]`. Exceções: `h1 { text-wrap: balance; }` a design spec pede em `@layer base` — seletor de elemento em `@layer base` NÃO é podado (o purge poda por classe utilitária; `base` com seletores de elemento é preservado, igual ao `:focus-visible` já existente no arquivo).

2. **Teste que lê `:root` por regex** (`.template-tests/test_07_tokens.py`): `_extract_block` captura de `:root {` até a PRIMEIRA linha `}\n` — declarações novas dentro de `:root` (como `color-scheme: light;`) são inofensivas; regras ANINHADAS dentro de `:root`/`[data-tema="escuro"]` quebrariam a captura. Não aninhar nada nesses dois blocos. `HEX_TOKEN_RE` só casa `--cor-*: #hex;` — nada a temer de declarações sem hex.

3. **Teste da safelist** (`test_safelist_bate_com_as_classes_declaradas_em_input_css`): faz `findall` de `\.(btn--primaria|…|results|module|form-row|btn)\b` sobre o CSS inteiro e compara CONJUNTOS com a safelist (8 entradas). Reaparições de `.results` ou `.btn` em regras novas não mudam o conjunto — seguro. NÃO criar classe de componente nova.

4. **Sem nesting de CSS:** o build é `npx tailwindcss@3.4.17` puro (Dockerfile) — sem plugin de nesting no pipeline. Toda regra nova é FLAT (ex.: `.results tbody tr:hover { … }`, nunca `&` aninhado). Declaração simples adicional dentro de um bloco `@apply` existente (ex.: `font-variant-numeric` dentro de `.results`) é válida.

5. **Runtime de marca:** `--cor-brand`/`--cor-brand-tint` são sobrescritas em runtime pelo `<style>` de `base.html` (core/tema.py) e pelo `[data-tema="escuro"]` — qualquer regra com `var(--cor-*)` acompanha tema e COR_PRIMARIA sozinha. Nunca hex literal.

6. **Overlay alvo em shell.html (linha ~55):**
   `<div x-show="sidebarAberta" x-cloak @click="sidebarAberta = false" class="fixed inset-0 z-40 bg-black/40 md:hidden"></div>`
   Única mudança permitida no template: acrescentar `backdrop-blur-sm` à lista de classes. (Nota da Fase 07-02: `backdrop-blur-xs` não gera regra no Tailwind 3.4.17; `backdrop-blur-sm` gera.)

7. **`#modal-container`** existe em `apps/{% if incluir_app_exemplo %}exemplo{% endif %}/` e em `.template-tests/fixtures/guia/apps/diarias/` — NÃO criar markup, NÃO editar esses diretórios.

8. Regra solta `.btn:active { transform: translateY(1px); }` FORA do media query (transform instantâneo é inofensivo com reduced-motion).
