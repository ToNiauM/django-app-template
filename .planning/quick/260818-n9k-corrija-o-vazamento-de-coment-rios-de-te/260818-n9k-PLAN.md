<objective>
Corrigir o vazamento de comentários de template Django exibidos como texto literal na
interface (tela de login e topo da página) e blindar contra regressão.

**Causa raiz (confirmada por inspeção):** o lexer de templates do Django
(`tag_re` em `django.template.base`) casa `{#...#}` SEM `re.DOTALL` — comentários
inline `{# #}` são válidos apenas em UMA linha. Quatro comentários no repositório
abrangem múltiplas linhas e, por isso, o Django os emite como texto literal no HTML:

1. `core/templates/base.html` linhas 20-22 (comentário hx-history, antes do `<body>` → aparece no topo da página)
2. `core/templates/core/_login_form.html` linhas 4-13 (fallback no-JS → aparece na tela de login, inclusive no swap htmx do partial)
3. `core/templates/core/shell.html` linhas 76-79 (hx-on::before-request do logout)
4. `core/templates/core/shell.html` linhas 83-87 (fallback no-JS do logout)

NÃO é problema de Copier/Jinja: `_templates_suffix: .jinja` no copier.yml faz o Copier
processar somente arquivos `*.jinja`; os `.html` são copiados verbatim. Nenhum `{#`
existe em arquivos `.jinja` de template (verificado por grep). Os comentários de UMA
linha (`base.html:6,9`, `login.html:6`, `shell.html:50,67`) são corretamente removidos
pelo Django e NÃO devem ser alterados.

**Correção:** converter os quatro comentários multilinha para
`{% comment %} ... {% endcomment %}` — o mesmo padrão já usado corretamente em
`base.html` (linhas ~15-19, comentário sobre o wrapper de centering). Nenhum conteúdo
explicativo é apagado; os comentários documentam decisões de segurança (CR-01, T-02-11)
e devem ser preservados integralmente.

Purpose: Interface limpa e, adicionalmente, eliminar divulgação de racional interno de
segurança no HTML servido ao cliente.
Output: Templates corrigidos + dois testes de regressão (estático no repositório do
template; renderizado no projeto gerado).
</objective>
