<!-- O executor deve usar este formato como base do snippet do bloco :80 no Caminho A. -->

Bloco :80 inicial (criado manualmente antes do certbot):

```nginx
server {
    server_name <hostname>;

    location / {
        proxy_pass http://127.0.0.1:<porta>;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
```

Após `sudo certbot --nginx -d <hostname>`, o certbot reescreve esse mesmo arquivo
adicionando o bloco 443 (ssl_certificate, options-ssl-nginx.conf, ssl-dhparams.pem)
e o redirect 301 do :80 — blocos marcados com "managed by Certbot".

O vhost renderizado pelo Copier (`ops/nginx/<slug>.conf`, fonte em
`ops/nginx/{{ sistema_slug }}.conf.jinja`) já traz os blocos 443 + redirect 301
prontos e por isso exige o certificado emitido ANTES (standalone com nginx parado).
Essa diferença de ordem é o motivo estrutural dos dois caminhos.
